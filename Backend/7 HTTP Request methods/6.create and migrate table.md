# 6. Creating and Migrating Tables with Drizzle ORM

In this guide, you will learn how to set up Drizzle migration tools, define a new database table in code, and push it to your PostgreSQL database using **Drizzle migrations**.

---

## The Big Picture: How Migration Works

```
drizzle.config.js (config)
        ↓
Write Table in schema.js  →  Generate Migration (SQL file in drizzle/)  →  Apply to PostgreSQL Database
      (JavaScript)                       (drizzle-kit generate)                    (drizzle-kit migrate)
```

---

## 1. What is a Database Schema?

A **database schema** is the blueprint of your database. It defines:
- What tables exist (e.g. `test_table`, `courses`).
- What columns each table has (e.g. `id`, `title`, `code`).
- What data type each column stores (e.g. numbers, text, dates).

Without a schema, the database would not know what shape your data should take.

---

## 2. What is a Drizzle ORM Table Definition?

In traditional SQL, you create a table by writing SQL commands directly into a database console:
```sql
CREATE TABLE courses (
  id bigint PRIMARY KEY NOT NULL,
  title varchar,
  code varchar
);
```

With **Drizzle ORM**, you define your tables directly in **JavaScript** using the `pgTable` helper function.  
This gives you autocomplete, type safety, and keeps your database structure saved in your project code.

## 3. Setup & Configuration: What We Added and Why

Before Drizzle can create migrations, it needs two things:
1. The migration CLI tool (`drizzle-kit`).
2. A configuration file (`drizzle.config.js`) so the CLI knows where your files and database are.

### A. Installing `drizzle-kit`

```bash
npm install -D drizzle-kit
```

- **Why:** `drizzle-orm` is the runtime library used in your application code to run queries. `drizzle-kit` is the companion CLI tool used during development to compare schemas, generate SQL migration files, and execute migrations.

---

### B. Creating `drizzle.config.js`

We created a new file named [drizzle.config.js](file:///c:/Users/USER/Desktop/T/Resources/Backend/3%20connect%20DB%20Connected/drizzle.config.js) in the project root:

```javascript
import { defineConfig } from "drizzle-kit";
import dotenv from "dotenv";

dotenv.config();

export default defineConfig({
  dialect: "postgresql",
  schema: "./schema.js",
  out: "./drizzle",
  dbCredentials: {
    url: process.env.DATABASE_URL,
  },
});
```

#### Why we created this file:
Without `drizzle.config.js`, Drizzle Kit has no idea where your project files live or which database to connect to. This file answers four essential questions:
- `dialect: "postgresql"`: Tells Drizzle Kit to generate PostgreSQL-compatible SQL syntax.
- `schema: "./schema.js"`: Tells Drizzle Kit where your JavaScript table definitions live.
- `out: "./drizzle"`: Tells Drizzle Kit where to save the generated `.sql` migration files (the `drizzle/` folder).
- `dbCredentials.url: process.env.DATABASE_URL`: Tells Drizzle Kit how to connect to your live database when running migrations.

4. **`"db:push"`:** A quick command (`npm run db:push`) to directly sync changes to the database without generating migration files.

## 4. How to Define a Simple Table in `schema.js`

Open [schema.js](file:///c:/Users/USER/Desktop/T/Resources/Backend/3%20connect%20DB%20Connected/schema.js).

We keep our existing `testTable` and add our new table, **`courseTable`**, right below it:

```javascript
import { pgTable, bigint, varchar, real, timestamp, text } from "drizzle-orm/pg-core";

// 1. Existing table (leave untouched)
export const testTable = pgTable("test_table", {
  id: bigint("id", { mode: "number" }).primaryKey(),
  name: varchar("name"),
  cgpa: real("cgpa"),
  created_at: timestamp("created_at", { withTimezone: true }).defaultNow(),
  password: text("password"),
});

// 2. New table: courses (added)
export const courseTable = pgTable("courses", {
  id: bigint("id", { mode: "number" }).primaryKey(),
  title: varchar("title"),
  code: varchar("code"),
});
```

### Explanation of the Columns:
- `pgTable("courses", ...)`: Tells Drizzle that the table in PostgreSQL will be named `"courses"`.
- `id: bigint("id", { mode: "number" }).primaryKey()`: An 8-byte integer column named `id` that serves as the table's primary key (unique identifier). `{ mode: "number" }` tells Drizzle to handle it as a regular JavaScript number.
- `title: varchar("title")`: A variable-length string column to store the course title (e.g. `"Data Structures"`).
- `code: varchar("code")`: A string column to store the course code (e.g. `"CSE101"`).

> **Note:** Defining this in `schema.js` only updates your JavaScript code. It does **not** change the database yet. To update the database, we must **generate** and **apply** a migration.

## 5. The `drizzle/` Folder: When and Why It Is Created

When you start the project, the `drizzle/` folder does **not** exist. You do **not** need to create it manually.

```
project/
├── drizzle/                     ← Created automatically by drizzle-kit
│   ├── meta/
│   │   ├── _journal.json        ← Tracks list of all migrations
│   │   └── 0001_snapshot.json   ← Blueprint of schema at migration 0001
│   ├── 0000_outstanding_hydra.sql
│   └── 0001_common_bullseye.sql ← Your new courses migration SQL
```

### When is the `drizzle/` folder created?
It is created **automatically the very first time you run `npx drizzle-kit generate`** (or `npm run db:generate`).

### Why is the `drizzle/` folder created?
1. **Configured location:** In `drizzle.config.js`, the line `out: "./drizzle"` tells Drizzle Kit: *"Store all generated migration output in this folder."*
2. **Version control history:** It stores the timeline of how your database changes over time.
3. **What is stored inside it:**
   - **`.sql` migration files:** Pure SQL scripts that can be applied to PostgreSQL.
   - **`meta/` folder:** Contains internal JSON snapshots (`_journal.json`, `*_snapshot.json`). Drizzle uses these to remember what your schema looked like so it can calculate future differences.

---

## 6. How and When Migration Files Are Added to `drizzle/`

### When are migration files added?
A new `.sql` file is added **every time you make changes to `schema.js`** (like adding a table, adding a new column, or changing a column type) and run:

```bash
npx drizzle-kit generate
```
*(Or `npm run db:generate`)*

### How Drizzle Kit adds them (step-by-step):
1. **Reads current schema:** Drizzle Kit parses your JavaScript code in `schema.js`.
2. **Checks previous state:** It checks the latest snapshot file inside `drizzle/meta/`.
3. **Calculates the diff:** It compares the previous snapshot with your new `schema.js` to see what changed.
4. **Generates the file:**
   - If changes are found, Drizzle Kit creates a new sequentially-numbered SQL file (e.g. `0000_...sql`, `0001_...sql`, `0002_...sql`).
   - It writes a new snapshot file into `drizzle/meta/` and updates `_journal.json`.
5. **If nothing changed:** If `schema.js` has no changes compared to the last snapshot, Drizzle Kit does not create any file and tells you `No schema changes detected`.

---

## 7. What a Migration File Contains

Open the newly created SQL file inside the `drizzle/` directory (for example, `drizzle/0001_common_bullseye.sql`):

```sql
CREATE TABLE "courses" (
	"id" bigint PRIMARY KEY NOT NULL,
	"title" varchar,
	"code" varchar
);
```

### Why migration files are useful:
- A migration file is an immutable history log of changes made to your database.
- It can be committed to Git so everyone on your team has the exact same database structure.
- You can inspect the exact SQL before applying it to your live database.

---

## 8. How to Apply the Migration to the Database

Generating the migration created the SQL file in `drizzle/`, but has not executed it on your PostgreSQL database yet.

To execute the SQL migration against your live PostgreSQL database, run:

```bash
npx drizzle-kit migrate
```

*(Or use the npm script: `npm run db:migrate`)*

### What happens when you run this:
1. Drizzle connects to your PostgreSQL database using `DATABASE_URL` from `.env`.
2. It looks at the internal tracking table in PostgreSQL (`drizzle.__drizzle_migrations`) to see which files have already run.
3. It runs any unapplied SQL migration files (like `0001_common_bullseye.sql`).
4. It records the migration in `drizzle.__drizzle_migrations` so it will never run twice.

You will see:
```
Using 'pg' driver for database querying
[✓] migrations applied successfully!
```

## 9. How to Verify That the Table Was Created Successfully

There are two easy ways to verify:

### Option A: Check with a quick Node script

Run this one-liner in your terminal:

```bash
node --input-type=module -e "import pool from './db.js'; const res = await pool.query('SELECT table_name FROM information_schema.tables WHERE table_schema = \'public\''); console.log(res.rows.map(r => r.table_name)); await pool.end();"
```

**Expected output:**
```
[ 'test_table', 'courses' ]
```
`courses` is now listed alongside `test_table` among your public tables!

---

### Option B: Query the table using Drizzle in your code

You can now use `courseTable` anywhere in your services:

```javascript
import db from "./drizzle.js";
import { courseTable } from "./schema.js";

// Fetch all courses
const allCourses = await db.select().from(courseTable);
console.log(allCourses); // []
```

## 10. Shortcut Approach: `npx drizzle-kit push` (Direct Push)

What if you do **not** want to manage, review, or store migration history files (`.sql` files) in a `drizzle/` folder?

For rapid prototyping or local development, Drizzle Kit provides a direct shortcut command:

```bash
npx drizzle-kit push
```

*(Or use the npm script: `npm run db:push`)*

### What `drizzle-kit push` does:
- It **does not create any `.sql` migration files** or update `drizzle/meta`.
- It connects directly to your PostgreSQL database.
- It **compares `schema.js` directly against the live database**.
- It immediately alters or creates tables and columns in PostgreSQL to match your current `schema.js`.

### When to use `migrate` vs `push`:

| Feature | `generate` + `migrate` (Tracked History) | `push` (Direct Sync) |
|---|---|---|
| **SQL Files Created?** | Yes (saved in `drizzle/`) | No SQL files created |
| **History Logged?** | Yes (recorded in `drizzle.__drizzle_migrations`) | No history log |
| **Safety / Review** | High — you can inspect the SQL before applying it | Low — executes changes immediately |
| **Best used for** | **Production & Team projects** | **Rapid prototyping & Local experimentation** |
